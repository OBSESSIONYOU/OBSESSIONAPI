# 渠道密钥响应脱敏设计

## 目标

管理后台继续支持新增、编辑、测试和加载渠道模型，但 `GET /api/channels` 不再把上游完整 API Key 返回给浏览器。

## 依据

- 当前前端编辑渠道时不会读取已有 Key；输入框留空后，后端会保留数据库中的原 Key。
- 参考 `D:\reference\new-api\controller\channel.go` 的渠道列表实现：查询列表时使用 `Omit("key")`，避免密钥进入响应。
- 现有真实推理测试、流式 `finish_reason` 修复、HTML 错误清理和 Docker 启动脚本已经存在并通过测试，因此本轮不重复实现。

## 设计

`channels_list` 仍从数据库读取渠道行用于内部处理，但在序列化返回前删除 `api_key`。不修改数据库结构，不改变创建、更新、模型发现和渠道测试对密钥的内部使用。

## 验收

1. 管理员请求 `GET /api/channels` 时响应不含 `api_key` 和真实密钥文本。
2. 编辑渠道时省略 `api_key`，数据库中的原 Key 保持不变。
3. 全部现有回归测试通过，Docker 镜像重建后健康。
